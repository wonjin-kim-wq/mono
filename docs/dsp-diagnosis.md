# 수정 전 DSP 진단과 변경 근거

기준 코드: Git 커밋 `9a50c3d` (수정 전에 조사한 상태).

| 항목 | 판정 | 근거 |
| --- | --- | --- |
| ScriptProcessorNode | 미사용 | 기존 `pitch.js:27–32`는 SoundTouch AudioWorklet + MediaElementSource. 메인 스레드 ScriptProcessor가 원인은 아님. |
| 오버랩/경계 | 내부 오버랩은 존재, 출력 부족·노드 교체에는 페이드 없음 | SoundTouch 2.1.1 번들의 `1461–1475`에 오버랩, `1905–1907`은 출력 부족분을 0으로 채움. 기존 `pitch.js:56–65`는 즉시 연결 교체. |
| 상태/버퍼 | 매 청크 초기화는 없음. 탐색 시 초기화, 출력 여유 부족 위험 | 기존 `app.js:108`, `pitch.js:56–65`. 번들 `1936–1957`은 Worklet의 128프레임 주기에서 가용 출력만 읽고 나머지는 0으로 채움. Worklet의 128프레임 quantum 자체는 정상이며 알고리즘의 분석 창 크기와는 다름. |
| 클리핑 | 실시간 출력 보호 없음 | 기존 `pitch.js:30`은 destination 직접 연결. 번들 `1895–1900`은 NaN 검사·피크 측정만 수행. 기존 파일 생성용 제한값 0.98도 −1dBFS 기준을 충족하지 않음. 기존 런타임의 실제 피크 초과는 측정 전에는 확정하지 않음. |
| 샘플레이트 | 파일/장치 레이트 불일치 가능 | 기존 `pitch.js:21`의 AudioContext는 장치 기본값, 등록 파일은 44.1kHz. 장치가 48kHz면 브라우저 변환 발생. 중복 변환이 모든 환경에서 발생한다고 단정할 수는 없음. |
| playbackRate/detune | 실시간 경로에는 해당 없음 | 기존 `pitch.js:33–36`은 rate=1. 다만 기존 등록 파일은 `asetrate + atempo`로 사전 변환되어 있었음 (`media/README.md:15`). |
| 누적 지연/메모리 | 측정·제어 부족, 누수 확정은 아님 | 번들 `1953–1957`은 underrun 횟수를 세지만 앱은 이를 제어에 이용하지 않음. 기존 앱에는 장시간 처리 기록, 오프라인 결과 캐시, 캐시 예산이 없었음. 기존 테스트는 3초 사인파여서 곡 끝 품질을 검증하지 못함. |

## 적용한 구조

1. 원본 메타데이터의 샘플레이트를 읽고 같은 레이트의 OfflineAudioContext로 디코딩.
2. Web Worker에서 Rubber Band 3.3.0의 R3 Finer, PitchHighQuality, ChannelsTogether, 표준 다중 해상도 창 사용.
3. 곡 전체 study → process 2단계. 16,384프레임 블록 사이에 상태를 유지하며, 오버랩과 위상 연속성은 엔진 내부에서 처리. 독립 청크들을 따로 변환하거나 이어 붙이지 않음.
4. timeRatio=1. 원본 길이와 엔진 출력 길이가 1프레임보다 많이 다르면 실패 처리. 추측한 지연을 잘라내거나 긴 무음을 덧붙이지 않음.
5. 전체 출력 피크를 스캔하고 필요할 때만 일정 게인으로 −1.1dBFS까지 감쇠. 다이내믹과 스테레오 균형을 유지. 파일 시작/끝 5ms 테이퍼.
6. 완성된 AudioBufferSourceNode를 1배속으로 재생. 재생 중 DSP 없음. 장치 레이트가 다르면 재생 출력에서만 브라우저의 최종 변환 발생.
7. 키 교체·탐색·재생·정지에 18ms 게인 페이드. 재렌더 중에는 기존 버퍼가 재생되고 완료 후 같은 시간 위치로 전환.
8. SHA-256 파일 내용 + 엔진 버전 + 샘플레이트 + 반음값으로 캐시. 메모리 LRU 160MiB, IndexedDB LRU 384MiB. 오래된 결과는 용량에 따라 제거되므로 모든 키가 영구히 메모리에 상주하지 않음.
9. 최신 요청만 적용. 이전 Worker 종료 및 버퍼 전송으로 취소·곡 전환 시 겹치는 처리 방지.

등록된 남자 원키도 제공된 −3 음원에서 R3 오프라인 +3으로 다시 만들었음. 기존 atempo 변환을 추가로 누적하지 않았음. 이후 키 변경은 캐시 결과를 재변환하지 않고 항상 디코딩한 원본에서 시작함.

## 검증 범위

- 44.1kHz/48kHz 사인파: −3, +3, +6반음 주파수, 스테레오 일치, 출력 길이, 피크 검사.
- 190.772초 실제 MR: +3, −3, +6의 전체 결과 및 처음/끝 30초의 무음 구간·레벨·블록 경계 검사.
- 전체 수치: `reports/audio-validation.json`. 원키 복원: `reports/master-restoration.json`.
- 자동 검사는 클릭·끊김의 구조적 원인과 수치상 회귀를 검사한다. 서로 다른 악기·음량을 가진 곡 처음과 끝의 주관적 음질이 동일하다는 청감 판정을 대신하지 않는다. 음정 이동 자체의 음색 변화는 남으며, UI에서 이를 안내한다.
